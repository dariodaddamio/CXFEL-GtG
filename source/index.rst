Guide to Guides
===============

*Last updated: November 2026*

Purpose
-------

The Compact Free Electron Laser (CXFEL) requires high-fidelity time integration and
synchronization between disparate hardware systems. CXFEL is working closely with a consultant/vendor, Osprey Distributed Control Systems (DCS), to develop such a system, which is known as the Data Acquisition System (DAQ), or more generally, the Event Timing (EVT) System. This document is meant to serve as a
guide to the guides, a way of grasping the system as a whole, for development and testing purposes.

Introduction
------------

The Data Acquisition System (DAQ), is composed of Event Generators (EVG) and Event Receivers (EVR). The EVG acts as the source of Time
Zero (T0), which is used to synchronize the timing system with the radio frequency (RF) system
and provide universal reference for all integrated diagnostics. The EVRs are distributed nodes
that "listen" to the timing signal sent by the EVG and translate it into local actions through event
codes. These EVGs and EVRs can be set up with both Analog (Quartz) or Digital (EVT) hardware provided by Osprey.

The original DAQ architecture proposal can be found :doc:`here </internal/daq_architecture_pdf>`, but some main takeaways are:

- **Timing chain**

  - Global Positioning System (GPS) satellites provide an absolute time reference (atomic clock).
  - A GPS antenna on the Biodesign roof is cabled through the lab, to a receiver such as a FS740 GPS receiver. The FS740 locks to those satellites and supplies the timing system with a stable
    **1 pulse‑per‑second (1 PPS)** and **10 MHz** reference.
  - The EVG synchronizes to this clock and generates a global **event stream** that encodes when things in the beamline should happen. 
  - The EVRs listen to that stream, translates event codes into hardware triggers/gates to local detectors, lasers, and other devices.
  - Detectors/DAQs record data in sync with those triggers, while Input/Output Controllers (IOCs) handle configuration, timestamps, and data flow. The Experimental Physics and Industrial Control System (EPICS) provides the surrounding control and monitoring layer.
  - Logs for every event are to be stored in a database for record keeping, and analysis.

In addition, the NSLS-II timing system was used as inspiration for the event stream format, the original file can be found :doc:`here </internal/nsls2_timing_pdf>`.

- **Event stream format:**

  - The timing stream carries an **8-bit event code** and a separate **8-bit
    distributed bus/data lane**. The second byte is not a verified per-shot metadata payload.
  - There are 256 possible code values (0–255), including predefined timing and control functions.
  - See :doc:`/event_codes/index` for existing practice and CXFEL options to compare.
